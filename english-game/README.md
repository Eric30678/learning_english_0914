# 情境英語遊戲 · 專案包

像素風的多益情境學習遊戲。兩個模式：**關卡**（做選擇、看後果）與**閱讀**（讀故事、點字查中文、聽朗讀、隔天小考）。

---

## 馬上玩

**開 `dist/index.html`**，五個模式都在那裡。
每個檔案都是單一 HTML、沒有外部依賴、離線可跑：

| 檔案 | 模式 |
|---|---|
| `dist/index.html` | 首頁 — 五個模式的入口 |
| `dist/game.html` | 關卡 — 做選擇、看後果 |
| `dist/read.html` | 閱讀 — 讀故事、點字查中文、朗讀、隔天小考 |
| `dist/listen.html` | 聽力 — Part 1–4，對齊多益規格 |
| `dist/cards.html` | 字彙對戰 — 一局 52 手，對面出英文、你出中文 |
| `dist/memory.html` | 翻牌配對 — 中英配對，跟電腦搶 |

## 開發

```
src/index.html      關卡模式（引擎）
src/read.html       閱讀模式（引擎）
src/listen.html     聽力模式（引擎）
src/cards.html      字彙對戰（引擎）
src/memory.html     翻牌配對（引擎）
src/data/*.js       全部內容，純資料，沒有邏輯
```

改內容只要動 `src/data/` 裡的檔案。引擎寫完就不太需要再碰。

改完要產出單檔：

```
python tools/build.py
```

會把 `src/` 的外部 js 內嵌，輸出到 `dist/`。

## 字型

用 **Cubic 11（俐方體 11 號）**，SIL OFL 1.1，可免費商用。

1. 到 <https://github.com/ACh-K/Cubic-11> 下載 `Cubic_11.ttf`
2. 放進 `fonts/`

沒放也能跑（會退回 CDN 或系統等寬字），但正式版建議自己託管。

**字級一律用 11 的倍數**（11 / 22 / 33px），其他尺寸會被抗鋸齒糊掉，失去點陣感。

要做成真正的單一檔案（字型也內嵌）：

```
pip install fonttools brotli
python tools/embed_font.py dist/read.html
```

會先做字型子集化，只保留內容用到的字，通常從 2MB 降到 100KB 以內。

### 字典（`dict.js`）

必須**最後載入**。做兩件事：

1. 自動收割 `chapters-*.js` 裡所有 `[字|中文]` 標記（約 1,000 筆），不用重打
2. 手動補上聽力獨有的字（約 200 筆）

引擎呼叫 `CONTENT.glossify(text)` 就能把一段英文包成可點的字。
聽力文字稿因此也查得到中文——**但只在作答之後顯示**，不影響聽的過程。

功能字（the、are、every…）刻意排除，否則整段變成一片虛線，
反而看不出哪些值得查。實測內容字覆蓋率約四成，密度剛好。

`OVERRIDE` 用來修正收割帶進來的語境偏差：
例如 `under` 在價目表那章是「未滿」，在其他地方是「在…下面」。

### 聽力（`listening.js`）

```js
part1: [{scene, tint, options:[四句], answer, note}]            // 不顯示文字
part2: [{skill, q, options:[三句], answer, note}]               // 不顯示文字
part3: [{level, words, intro, scene, tint, lines:[['M','…'],['W','…'],['M2','…']], qs:[…]}]
part4: [{level, words, intro, scene, tint, lines:[['W','…']], qs:[…]}]
```

講者代號 `M` / `W` / `M2`，三人對話用得到。
系統有兩個以上英文語音時 W 用第二個，M2 一律靠音高區分。

**Part 2 的 skill 標籤**（練聽力才需要的難點）：

| 值 | 練什麼 |
|---|---|
| `number` | fifteen / fifty、報號碼、報金額 |
| `sound` | 近音：whether / weather、leave / live |
| `reduce` | 縮讀：wanna、d'you、I'd've |
| `correct` | 改口：Actually… / I mean… |
| `wh` | 疑問詞配對 |
| `statement` | 非問句的回應 |

**聽力總量**（真實多益：P1 六題、P2 二十五題、P3 三十九題、P4 三十題）：

| Part | 題數 | 長度範圍 |
|---|---|---|
| 1 · 照片描述 | 18 | — |
| 2 · 應答問題 | 44 | — |
| 3 · 簡短對話 | 29（10 組） | 24–105 字 |
| 4 · 簡短獨白 | 27（9 組） | 32–110 字 |
| **合計** | **118** | |

Part 2 的技能分布：number 12 · sound 9 · reduce 8 · correct 7 · wh 4 · statement 4

長度分級最後一級就是真實考試規格。L1 只有兩三句，用來確認機制。

**聽力內容一律用全新情境。** 字彙刻意沿用前面章節，
但句子和情節不重複——否則玩家練到的是回憶，不是解析。
建置時用腳本比對過，確認沒有任何句子與閱讀章節重疊，
聽力兩批之間也沒有重複。

場景涵蓋：機場 · 診所 · 車行 · 飯店 · 工地 · 藥局 · 銀行
搬家公司 · 火車站 · IT 客服 · 博物館 · 健身房 · 碼頭```

Part 1／2 作答前完全不顯示文字，跟真實考試一樣。
作答後才放出文字稿與解說——那是學習需要，考試沒有。

Part 1 的「照片」直接用既有的像素場景。

### 字彙對戰（`cards.html`）

牌庫**不是另外寫的**，是從 `CONTENT.dict` 自動生成，
所以前面所有章節、關卡、聽力教過的字都會自動進牌庫。

規則：

- 一局 **52 手**，手上固定 **8 張中文牌**
- 對面出一張英文牌，那個字一定在你手上，所以永遠猜得到
- 出對就換一張新牌，出錯的字留在手上，等一下還會再遇到
- 錯過的字跨局累計。錯 1 次權重 ×3、2 次 ×5、**3 次以上 ×8**
- 結算列出本局錯的字，以及累計「還沒記起來」的清單
- 按數字鍵 1–8 也能出牌

三種出題範圍：全部字庫 / 只出我記不住的 / 只出重點字。

**牌庫篩選**（避免出現 i、you、me 這種沒意義的題目）：

| 條件 | 說明 |
|---|---|
| 長度 < 3 | 濾掉 |
| 在基礎字清單裡 | 濾掉（含數字、顏色、基本動詞） |
| **變化形還原後是基礎字** | 濾掉（called ← call、cheapest ← cheap） |
| 中文只有一個字 | 濾掉（「等」「筆」當選項無法分辨） |
| 中文與其他字重複 | 濾掉（避免同時出現兩張正解） |

字典 1,491 筆 → 牌庫 **999 字**（其中重點字 399）。

### 新單字庫（`vocab-extra.js`）

**閱讀內容裡不會出現的字**，純粹用來補量。劇情要服務故事，
不能為了塞字硬寫；所以把「要背的字」拆出來放進兩個遊戲當題庫。

分兩批，合計 **1,355 字**：

- `vocab-extra.js`（602）商務動詞名詞、形容詞、副詞連接、片語動詞、
  人事、財會、生產物流、行銷、資訊、旅行、法務、學術論述、易混淆字組
- `vocab-extra-2.js`（753）趨勢圖表、進階動詞名詞、人格形容詞、
  保險風險、銀行投資、房地產、醫療、教育、環境能源、餐飲零售、
  媒體活動、公共事務、第二批片語動詞、動名搭配、第二批易混淆字組

兩批都會在載入時自動去重：與 `dict` 重複的、彼此重複的、
中文撞號的全部移除（配對不能出現兩張正解）。

兩個遊戲因此有五種出題範圍：

| 模式 | 來源 |
|---|---|
| 舊單字 · 章節教過的 | `CONTENT.dict` |
| **新單字 · 閱讀不會出現** | `CONTENT.extraVocab` |
| 兩邊混合 | 全部 |
| 只出我記不住的 | 兩邊裡錯過的字 |
| 只出重點字 | 核心字 |

中文一律 2–6 字且不重複，否則配對會出現兩張正解。

**字會自己畢業。** 把某個新單字寫進閱讀章節之後，
`dict.js` 收割時會抓到它，`vocab-extra` 的去重就會把它從
「新單字」移除——它自動從純背誦變成「章節裡見過」。
第八輯就是這樣把 120 個字從新字庫搬進情境的，
不需要手動搬任何一筆。

### 翻牌配對（`memory.html`）

中英配對的記憶遊戲，跟電腦輪流翻。牌庫與字彙對戰共用。

- 開局**先把全部的牌翻開複習一次**，秒數依牌數而定
- 配對成功可以繼續翻（標準規則）
- 6 / 8 / 10 對可選，另有**單局 / 三局制 / 五局制**
  （手機上一超過 20 張牌字就看不清楚，所以要份量請用局數堆，不要加牌數）
- 系列賽中途顯示局分，打完才總結算
- 結算列出雙方各拿到哪些字，可一鍵把「被電腦贏走的」加進複習清單
  （寫入 `pxcards.v1`，字彙對戰會優先出這些字）

**電腦的記憶力是可調的，這是刻意的設計。**

完美記憶的電腦在這個遊戲裡幾乎必勝——玩家每翻錯一次，
那兩張牌的位置就等於送給它。所以做成 `retain` 參數：
每看到一張牌，只有該機率會被記住，記憶力越差也越容易遺忘。

| 檔位 | retain |
|---|---|
| 健忘 | 0.45 |
| 普通 | 0.70 |
| 很強 | 0.90 |
| 完美記憶 | 1.00（幾乎贏不了，留給想挑戰的人） |

玩家真正的優勢在於：**電腦記位置，你記意思。**
有意義的材料本來就比較好記，這是可以贏過它的地方。

牌面排版限制：中文 2–6 字、英文 ≤16 字元，超過的不進牌庫。

## 內容結構

### 關卡（`content.js` / `season2.js`）

一集的形狀：

```js
{
  id: 44, scene: 'office', actor: 'david', stage: 'L5',
  n: '情境敘述（一句一行）',
  goal: '這一關要達成什麼',
  w: ['目標字'],
  o: [
    // [英文選項, 判定, 結果標題, 後果, 為什麼]
    ['Can Sam check the numbers?', 'ok', '他直接批了', 'David：「…」', '講缺口的同時給出人選。'],
  ]
}
```

判定：`ok` 最佳 ／ `mid` 不精確或中文思維 ／ `bad` 當下爽後果爛。
每集四個選項，四種類型各一個。

### 閱讀章節（`chapters.js` / `chapters-2.js`）

```js
{
  id:'c1', title:'The Last Truck', zh:'最後一班車', blurb:'一句簡介',
  long: true,               // 長篇：字級自動縮小
  pages: [ {scene:'warehouse', tint:'dark', t:'…'} ],
  quiz: [ ['題目', ['選項…'], 正解索引, '解說'] ]
}
```

文字標記：

| 寫法 | 意思 | 顯示 |
|---|---|---|
| `[word\|中文]` | 一般可點字 | 細虛線 |
| `*[word\|中文]` | 本章重點字 | 金色粗虛線 |
| `~[word\|中文]` | 回收字（之前教過） | 綠色粗虛線 |

### 場景與光線

場景 SVG 分三個檔，共十四個：

| 檔案 | 場景 |
|---|---|
| `content.js` | `office` |
| `scenes-extra.js` | `counter` `street` `room` `meeting` `warehouse` |
| `listening.js` / `listening-2.js` | `airport` `port` |
| `scenes-more.js` | `desk` `lobby` `factory` `cafe` `corridor` `shopfloor` |

`desk` 是唯一換了**鏡頭距離**的一個——桌面特寫。
六十四章裡有二十幾章其實是在讀文件（發票、合約、email、公告），
那些用桌面特寫比用房間空景準確得多。

**`scenes-more.js` 必須放在所有 `chapters-*.js` 之後載入**，
因為它最後會用一張對照表蓋掉配錯的場景。

光線用 `tint` 疊一層半透明色：
`day` `dusk` `night` `dark` `storm` `dawn` `warm`

**換光不換景**，所以新增一章的美術成本接近零。

## 設計上的硬規則

寫新內容時這幾條不要破：

1. 選項長度差不超過 1.3 倍，否則玩家會靠長度猜答案
2. 選項用字在同一難度帶，差異只出現在策略
3. 選項裡不出現本集的目標字
4. 生字密度 2–3%，而且每個生字都要通過遮字測試（蓋掉還讀得懂）
5. 「為什麼」用中文，講機制不講文法規則
6. 情境描述的英文化進度和內容難度是兩條軸，一次只動一條

細節見 `docs/` 裡的四份規格。

## 已知限制

- **聽力**：全部用瀏覽器內建語音合成，不需音檔。缺點是唸得出字但唸不出語氣，也沒有真實口音差異（多益有美、英、加、澳四種）。適合練聽字、聽數字、練題型反應，不適合當成正式模擬。
- **縮讀題**：wanna、d'you 這類寫法語音合成唸得出來，但唸得比真人清楚。真實口語會更難。
- **三人對話**：系統通常只有一到兩個英文語音，第三個講者靠音高區分，聽起來不如真人自然。
- **iOS Safari**：第一次播放必須由使用者點擊觸發，系統限制。
- **逐字高亮**：依賴 `onboundary`，部分瀏覽器不回報，那就只有聲音沒有高亮。
- **字彙量**：711 個主動字彙、題庫 3,056 字、約 3,000 個被動詞元。這是多益 700 分字彙門檻的下緣，但字彙只是其中一項，距離多益 700 分一般估計需要的 3,000–4,000 辨識量仍有距離（一般估需 3,000–4,000 字辨識量），這套系統的定位是主動使用與語感，不是字彙廣度。
